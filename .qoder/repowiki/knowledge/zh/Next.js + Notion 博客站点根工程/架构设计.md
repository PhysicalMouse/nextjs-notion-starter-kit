根目录承担三件事：
- 入口与运行时装配：`next.config.js` 声明远程图片白名单（notion.so / unsplash / twitter / s3）、AVIF/WEBP 输出格式与 `react-tweet` transpile；`site.config.ts` 导出站点级元信息（rootNotionPageId、domain、analytics、revalidateSeconds 等），由 `lib/site-config.ts` 统一解析。
- 共享数据层 `lib/`：`notion-api.ts`、`resolve-notion-page.ts`、`map-page-url.ts`、`get-site-map.ts`、`search-notion.ts`、`acl.ts` 等模块被 `pages_and_routes` 的 API 路由与 `notion_lib` 的 PageProps 注入逻辑共同消费，是 pages 与 ui_components 之间的唯一数据契约。
- 子模块职责边界：`pages_and_routes` 负责 Pages Router 端点与 ISR revalidation；`ui_components` 基于 react-notion-x 渲染页面；`notion_lib` 封装 Notion SDK 调用与缓存；`styles` 提供全局主题覆盖。三者均不直接依赖 Notion SDK，而是通过 lib 暴露的类型与函数协作。
- 构建与部署：`vercel.json` + `pnpm-workspace.yaml` 指定 Node 24 与 pnpm 10，`package.json` 脚本仅转发到 next dev/build/start/deploy，本地开发时通过 `deps:link:*` 脚本把 `react-notion-x` 及 notion-* 包 link 到上游仓库以便联调。
